# Publishing project changes

After completing a requested project change, run the relevant checks, commit the files changed for that task, and push to the configured GitHub upstream. The project owner has authorized this as the default for future Codex changes in this repository.

Keep generated reports, AIS downloads, credentials, and unrelated local files out of commits. Preserve existing user changes and use a normal push. If checks fail or Git rejects the push, diagnose the failure and report any remaining blocker. Follow a newer user instruction to keep a particular change local.
